# Ferrow Foresight: Notable Defects Fixed

*Curated changelog of critical technical and operational defects identified during functional testing, multi-browser verification, and assessor walk-throughs, documenting root causes and resolutions in product language.*

---

## Defects & Operational Enhancements Table

| # | Issue Area | Commit | Problem Identified | Resolution in Product Language |
|---|---|---|---|---|
| **1** | **Vercel Static vs. Dynamic Rendering** | `981bb60` | Dynamic routes with query parameters (`?plant=`, `?line=`) were being statically cached at build time on Vercel, causing stale data on navigation. | Added `export const dynamic = 'force-dynamic'` and `Suspense` boundaries across operational pages, ensuring real-time URL context and telemetry updates. |
| **2** | **Captured Alert Validation & Ingestion** | `752d03e` | Newly submitted technician floor observations occasionally failed schema validation due to missing optional machine IDs, dropping out of the Planner queue. | Hardened `TriageOutputSchema` normalization and alert ID generator to automatically synthesize valid alert entities and queue them immediately in `pending` state. |
| **3** | **Design System: Dark Mode Removal** | `c6ebe32` | Legacy dark mode theme caused poor contrast on industrial displays and violated Project Spec Section 6 ("Day shift light mode only"). | Completely removed the night mode toggle, standardizing the application on the ISA-101 high-performance light palette (`--canvas: #F5F6F8`, `--ink: #1E252B`). |
| **4** | **Technician Shift Matching & Roster Logic** | `55e7aab` | AI triage occasionally recommended qualified technicians rostered on Shift A for maintenance windows scheduled during Shift C, causing operational conflicts. | Implemented automated shift-window guardrail check (`checkShiftMatch`) and enforced shift-aligned qualified technician and junior trainee shadow pairings at alert load. |
| **5** | **Execution Gating & Mandatory LOTO** | `81548fa` | Maintenance task steps were clickable before zero-energy LOTO verification was finished, posing an industrial safety compliance risk. | Implemented strict two-phase execution gating: Phase 2 maintenance task checklist remains hard-locked until all 6 Phase 1 LOTO steps are verified and a permit number is issued. |
| **6** | **Seeded State Consistency on Demo Reset** | `9cafd33` | Clicking "Reset demo" occasionally left partially executed work orders in Supabase while in-memory state reverted, causing "Work order not found" errors. | Unified the reset handler in `/api/demo/reset` to atomically synchronize and restore all canonical work orders (WO-2201, WO-2202, WO-2203) across both database and disk backends. |
| **7** | **Elimination of AI Calls on Page Load** | `6edeedc` | Visiting `/planning` or `/status` triggered background live AI agent calls automatically, rapidly depleting hourly API rate limits and causing unnecessary latency. | Refactored page loaders to read cached baseline recommendations by default; live AI execution now triggers strictly upon explicit user interaction ("Run PM Optimiser"). |
| **8** | **Dual Authorization Guardrail Clarity** | `f9ea92d` | P1 alerts on Criticality A machines showed a generic red guardrail failure before Plant Head approval, confusing planners about why the alert was held. | Refactored guardrail check `criticality_a_p1` to explicitly display an amber "Requires Plant Head approval (pending)" status with guidance on dual authorization. |
| **9** | **Evidence Guardrail False Positives** | `5961e70` | Guardrail Rule 2 failed alerts that had valid sensory evidence text but did not explicitly cite numerical token IDs like `E1` in their assessment sentences. | Updated `checkEvidenceIdsExist` to validate that alerts contain at least one structured evidence item and verify citations only when formal `E#` tokens are referenced. |
| **10** | **Data-Driven KPI Target Alignment** | `2d717fe` | Pilot KPI improvement targets on `/kpis` were computed on an inconsistent annual basis rather than against the actual April–September 2026 historical baseline. | Standardized KPI target calculations to derive pilot targets directly from the 6-month historical baseline (14.2% PM compliance uplift, 18.5% downtime cost reduction). |
| **11** | **Work Order Window Confirmation Lookup** | `ea0b54e` | Work order execution pages occasionally lost confirmation state for production windows when navigating between different operational personas. | Standardized `isWindowConfirmed` and `isSparesConfirmed` in `lib/workflow.ts` as the single canonical source of truth across all components and API handlers. |
| **12** | **Windows Desktop Launcher Syntax** | `795d16e` | Windows batch file `Start Ferrow (Windows).bat` threw syntax errors on systems without pre-installed npm paths due to improper variable quotation. | Rewrote launcher batch script defensively with comprehensive environment variable checks, graceful fallback paths, and clear user diagnostic prompts. |
| **13** | **Plant Copilot Safety Policy Grounding** | `ea0b54e` | Copilot occasionally generated overly verbose responses or flagged upcoming non-expired LOTO certifications as immediate compliance blockers. | Grounded Copilot prompt with strict domain rules: concise answers with factual citations, non-blocking 30-day warnings for soon-expiring certs, and absolute refusal for LOTO bypass. |
| **14** | **Cross-Platform Script Standardization** | `f188f62` | NPM build scripts failed on Windows environments due to POSIX-specific inline environment variable assignments (`NODE_ENV=production`). | Integrated `cross-env` across all `package.json` scripts, guaranteeing identical headless execution across macOS, Linux, and Windows. |
